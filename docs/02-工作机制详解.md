# 02 · 工作机制详解

> 这份文档回答：**这个 skill 内部是怎么运转的，每一步在干什么，防错点在哪。**

## 整体结构

```
kpf-writing-grading/
├── SKILL.md                      # 主流程：六步 + 红线 + 校准机制
├── rubrics/
│   ├── ket.md                    # KET 评分标准
│   ├── pet.md                    # PET 评分标准
│   └── fce.md                    # FCE 评分标准
├── assets/
│   └── report-template.html      # HTML 报告模板（含虚构示例）
├── scripts/
│   └── validate-deliverables.py  # 交付前校验器
├── tests/                        # 已校准回归测试场景
└── CHANGELOG.md                  # 校准日志（每次规则演进的记录）
```

四类文件，各管一件事：**流程**（SKILL.md）、**标准**（rubrics）、**产出**（assets）、**卡口**（scripts + tests + CHANGELOG）。

## 六步流程

### 第 0 步：确认上下文

**做什么**：确认批改需要两个材料——作文题 + 作文本身。级别和题型从题目判断。

**防错点**：
- 缺题目就问，不猜（Content 分要按题目要点核对，没有题目无法评分）
- 题目照片看不清、信息不全，同样先问
- 提供了学生姓名时，先查归档目录里有没有该生的历史档案，有则延续观察点

**为什么重要**：AI 自然倾向是「先改再说」。这一步把它按住了——没有题目，Content 分就是瞎打。

### 第 1 步：OCR 转写 + 确认

**做什么**：把图片中的手写作文（和题目）转写成文字，统计字数，报告词数要求，然后**停下来等确认**。

**防错点**：
- 认不准的词标 `[?]`，绝不猜一个顺眼的写上去
- 字数必报，不估算
- 用户直接贴文本也要确认（贴的可能有遗漏）

**为什么重要**：这是整个流程的「安全阀」。手写识别不可能全对，但认错一个字就可能让学生被误判。确认这一步把风险转移给了你——你看一眼，比我猜一次准。

### 第 2 步：按官方标准评分

**做什么**：按级别读对应 rubric，四项（KET 三项）各打 0–5 分，每项给分依据必须能指向具体句子。

**防错点**：
- **先执行字数硬线**：词数未过线直接判不过（分数照常评出供参考，但不写 Grade 档位）
- Content 分逐条核对题目要点，漏答的必须明确指出
- 档位说明四选一：Grade X 通过 / Grade X 边缘，未稳过 / 未过字数线判不过 / 未达到本级要求

**为什么重要**：这是「不凭感觉打分」的落点。每个分数都要能说出「为什么给这个分」，给不出依据的分会被校验器拦下。

### 第 3 步：逐句批改

**做什么**：按原文顺序逐句列出错误，每条给「原句 → 问题分类 → 改法」。

**防错点**：三类处理边界——
- **错误**（必须改，计入分数）：语法、拼写、标点等影响准确性的
- **可选优化**（标出来但不计分）：不算错但可更地道的表达（典型：characters 指「性格」不算错，换 personalities 更贴切）
- **保留**（标出来并一句带过为什么好）：写对的、值得保留的句子

**为什么重要**：上一轮审查发现，把「可选优化」当「错误」计分是真实发生过的误判。三类边界把这个区分开了。

### 第 4 步：修改后范文

**做什么**：给「跳一跳够得着」的版本——以学生的句子和用词为基础做最小必要修改，不是拔高到满分的炫技版。

**防错点**：改动处用粗体标出；如果改动超过一半，额外说明「建议重点看批改清单」。

**为什么重要**：拔高版学生抄了也学不会；reachable 版才能对照着学。

### 第 5 步：学生版纯文本反馈

**做什么**：按定稿格式输出五个【】分区的纯文本反馈。

**防错点**（三条红线）：
- 纯文本，不用 Markdown
- 禁破折号（—— 和 —）
- 禁「不是…而是…」「不仅仅…更…」句式

**交付前必跑校验器**。

### 第 6 步：完整 HTML 报告

**做什么**：生成单文件 HTML 报告，六个区块（抬头 + 01–05），右下角有「生成图片（发家长）」按钮。

**防错点**：
- **不嵌图片**（原题和原文只放文字转写）
- **不出现学生版反馈段**（两个交付物内容不重复）
- 数字必须实际计数，不许估算
- 交付前跑校验器（**两个文件一起传**，触发跨文件一致性检查）+ Chrome 无头截图目检

## 三套 rubric 的结构

每份 rubric（KET / PET / FCE）都是同一个结构，分四层：

| 层 | 内容 | 来源 |
|---|---|---|
| 1. band descriptor | 官方评分标准的 1/3/5 分档描述 | 剑桥官方教师指南 |
| 2. 官方样文锚点 | 真实评过分的样文 + 分项分数 + 关键判据 | 剑桥官方 handbook |
| 3. 教研共识 | 教学实践中总结的判分技巧 | 新东方等教研 |
| 4. 自定规则 | 字数硬线、定性档位 | 本 skill 定义（可改） |

**改任何一处之前，先看它属于哪一层。** 改第 1、2 层需要对照官方 handbook 复核；改第 3、4 层是你自己的事。

## 校验器的工作原理

`scripts/validate-deliverables.py` 在每次交付前运行，做三类检查：

**1. 文本反馈检查**（`check_feedback`）
- 五个【】分区齐全且顺序对
- 无破折号、无「不是…而是…」句式
- 重要性星级 3 条且严格递减
- 分数算术：小分维度齐全（KET 三项 / PET·FCE 四项）、单项 0–5、总分=小分和、满分与级别匹配、无小数、无负数、档位与分数落在定性档位表对应区间

**2. HTML 报告检查**（`check_html`）
- 必要元素齐全（分区、截图按钮、html2canvas）
- 禁用内容不回流（学生版反馈段、受众标签、教师工作语言）
- 无未替换占位符、无模板残留数据
- 抬头分数区与文本反馈走同一套算术校验

**3. 跨文件一致性检查**（`main`，两文件同传时触发）
- 总分一致
- 小分一致
- 结论一致（是否判不过）

**自检**：`python3 scripts/validate-deliverables.py --selftest` 会跑 16 条已知反例+正例，确认校验器本身没有被改坏。

## 校准回路

这个 skill 靠真实批改反馈持续进化，不是一次性产品：

1. **分类**：老师贴回改法 → A 一次性误判 / B 规则缺陷 / C 新场景 / D 自定规则调整
2. **回归测试**：B/C 类改动用 `tests/` 里已校准场景重放验证
3. **记 `CHANGELOG.md`**：每条含日期、类别、输入摘要、原行为、改动、测试结论
4. **同步**：本地母本攒一批后脱敏同步到公开仓库

`tests/` 里目前有三个已校准场景（PET 未过线 / KET 未过线 / PET 过线 Grade B），每次改规则都要拿它们回归。

## 三层防错体系

整个 skill 的可靠性不是靠任何单一机制，而是三层叠加：

```
第 1 层：流程约束（不许猜、先确认、挂量表）
    ↓ 挡住「AI 自然倾向」的错误
第 2 层：标准锚定（band descriptor + 官方样文锚点）
    ↓ 保证评分有据可依，不是感觉
第 3 层：机器卡口（校验器 + 自检 + 跨文件一致性）
    ↓ 抓住前两层漏掉的算术错误、格式错误、矛盾
```

任何一层单独都不够，三层叠起来才能说「可靠」。
