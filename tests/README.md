# 回归测试语料 · tests/

> 每个 `.md` 文件是一个已校准的测试场景：输入（题目+作文转写）+ 老师确认过的期望输出要点。
> 每次改 SKILL.md 或 rubrics 后，用这些场景跑子代理回归测试，确认修复生效、其他场景没碰坏。
> **语料脱敏规则**：作文可以是学生真实作文的匿名改写（改人名、细节），但评分期望必须是老师确认过的真实结论；学生一律化名。

## 场景清单

| 文件 | 级别/题型 | 场景 |
|---|---|---|
| `case-01-pet-article-fail.md` | PET Part 2 article | 51 词未过线 → 判不过 + 反馈照常产出（已校准：10/20，边缘） |
| `case-02-ket-story-fail.md` | KET Part 7 story | 19 词未过线 + KET 三项 + 档位标注（已校准） |
| `case-03-pet-article-pass.md` | PET Part 2 article | 91 词过线 → 16/20 Grade B（已校准：四项 4/4/4/4） |

## 新增场景的方法

1. 真实批改出现新情况（新题型、新分歧、新规则）且老师确认结论后
2. 把输入和期望结论写成一个 case 文件（格式参照已有文件）
3. 在 CHANGELOG.md 记一条 C 类记录

## 回归测试跑法

改动 SKILL.md / rubrics 后，对每个受影响的 case 派子代理重放：
系统上下文 = SKILL.md + 对应 rubric 全文 + case 的输入部分；
判定 = 子代理输出与 case 期望要点逐条对照，全部命中才算通过。
